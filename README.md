### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут управлять отоплением в доме
- В доме может быть расположено несколько датчиков температуры
Основная информация о датчике:
	* Индентификатор (Id)
	* Наименование (Name)
	* Тип (Type)
	* Место раположения датчика (Location)
	* Текущее значение температуры (Value)
	* Единицы измерения (Unit)
	* Состояние (Status)
	* Дата последнего обновления информации (LastUpdated)
	* Дата создания (CreatedAt)
- Система поддерживает вывод списка датчиков в доме
- Система поддерживает вывод информации о текущем состоянии датчика по идентификатору
- Система поддерживает регистрацию датчика при включении (создание датчика). При первом создании датчика его статус - inactive (неактивен).
- Система поддерживает обновление информации по датчику.
	При каждом вызове метода обновляется последняя дата обновления. Также обновляются данные по полям: Name, Type, Location, Unit, Status (в случае, если значения заполнены).
- Система поддерживает удаление датчика 
- Система поддерживает обновление информации о значении температуры (Value) и состоянии датчика (Status)


**Мониторинг температуры:**

- Пользователи могут проверять температуру в доме
- Система поддерживает вывод информации о температуре в доме по месту расположения
- Система поддерживает вывод информации о температуре по конкретному датчику
Основная информация о температуре:
* Текущее значение температуры (Value)
* Единицы измерения (Unit)
* Место раположения датчика (Location)
* Состояние (Status)
* Индентификатор датчика (SensorID)
* Тип датчика (SensorType)
* Описание (Description)

### 2. Анализ архитектуры монолитного приложения

- Нынешнее приложение компании позволяет только управлять отоплением в доме и проверять температуру.
- Каждая установка сопровождается выездом специалиста по подключению системы отопления в доме к текущей версии системы.
- Архитектура приложения представляет из себя монолит на Go с СУБД Postgres. Всё синхронно. Никаких асинхронных вызовов, микросервисов и реактивного взаимодействия в системе нет. Всё управление идёт от сервера к датчику. Данные о температуре также получаются через запрос от сервера к датчику.
- Самостоятельно подключить свой датчик к системе пользователь не может.

### **4. Проблемы монолитного решения**

- Синхронное взаимодействие, запросы обрабатываются последовательно
- Ограничена масштабируемость
- Развертывание требует остановки всего приложения
